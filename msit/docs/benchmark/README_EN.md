
# msit benchmark Feature Usage Guide

## Introduction

This document introduces the benchmark feature, which is used to run inference programs for a specified inference model and test the performance of the inference model (including throughput and latency).

## Usage

### Feature Introduction

#### Usage Entry

The benchmark inference function can start model testing directly through the msit command line. The startup method is as follows:

```bash
msit benchmark --om-model *.om
```

where * is the OM offline model file name converted through the ATC tool.

#### Security Risk Warning

Before the model file is loaded by the tool, the user must ensure that the input file is safe and trustworthy. If the model file source officially provides a checksum value such as SHA256, the user must verify it to ensure that the model file has not been tampered with.

#### Parameter Description

The benchmark inference function can handle various test scenarios and implement other auxiliary functions by configuring different parameters.

Parameters are divided into **basic function parameters** and **advanced function parameters** by function category:

- **Basic function parameters**: Mainly include input file and format, debug, inference count, warm-up count, specified running device, and help information.
- **Advanced function parameters**: Mainly include benchmark inference test parameters for dynamic grading scenarios and dynamic shape scenarios, as well as profiler or dump data acquisition.

**Description**: In the following parameters, the parameter and value can be separated by a space " " or by an equals sign "=". For example: --debug 1 or --debug=1.

##### Basic Function Parameters

| Parameter                     | Description                                                                                                                                                                                     | Required |
|-------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------| -------- |
| -om, --om-model         | The OM offline model file to be used for inference.                                                                                                                                                                        | Yes       |
| -i, --input              | Model input. You can specify the directory where the input files are located or directly specify the input file. Supported input file formats are "NPY" and "BIN". Multiple files or directories can be input, separated by commas. Prepare the input files according to the model requirements. If this parameter is not configured, input data is automatically constructed. The input data type is determined by the --pure-data-type parameter.                                                  | No       |
| -pdt, --pure-data-type   | Pure inference data type. Values: "zero" and "random". The default value is "zero". When the model input file is not configured, the tool automatically constructs input data. When set to zero, pure inference data filled with zeros is constructed. When set to random, a set of random data is generated for each input.                                                                                | No       |
| -o, --output             | Inference result save directory. When configured, a "date+time" subdirectory is created to save the output results. If the --output-dirname parameter is specified, the output results are saved to the subdirectory output dirname. When the output directory is not configured, only the output results are printed and not saved.                                                                                | No       |
| -od, --output-dirname    | Inference result save subdirectory. When this value is set, the output results are saved to the *output/output-dirname* directory. Used together with the output parameter. Invalid when used alone. For example: --output */output* --output-dirname *output-dirname*                                                             | No       |
| --outfmt            | Output data format. Values: "NPY", "BIN", and "TXT". The default is "BIN". Used together with the output parameter. Invalid when used alone. For example: --output */output* --outfmt NPY.                                                                                            | No       |
| --debug                   | Debug switch. Prints model desc information and other detailed execution information. 1 or true (enabled), 0 or false (disabled). Disabled by default.                                                                                                                                   | No       |
| -rm, --run-mode                | Data loading method before inference execution. Available values: array (convert data to ndarray on the host side, then call the inference interface for inference), files (load files directly into the device, then call the inference interface for inference), tensor (load data into the device, then call the inference interface for inference), full (convert data to ndarray on the host side, then load the ndarray format data into the device, then call the inference interface for inference). The default is array. | No |
| -das, --display-all-summary     | Whether to display all summary information, including h2d and d2h information. 1 or true (enabled), 0 or false (disabled). Disabled by default.                                                                                                                                        | No       |
| --loop                    | Number of inference iterations. The default value is 1. The value range is positive integers greater than 0. When the profiler parameter is set to true, it is recommended to set it to 1.                                                                                                                                        | No       |
| -wcount, --warmup-count  | Number of inference warm-up iterations. The default value is 1. The value range is integers greater than or equal to 0. Setting it to 0 means no warm-up.                                                                                                                                                     | No       |
| -d, --device             | Specify the running device. Specified by the actual Device ID of the device. The default value is 0. In multi-device scenarios, multiple devices can be specified for inference testing at the same time, for example: --device 0,1,2,3.                                                                                                       | No       |
| --divide-input            | Input dataset splitting switch. 1 or true (enabled), 0 or false (disabled). Disabled by default. In multi-device scenarios, when enabled, the tool evenly distributes the dataset to these devices for inference.                                                                                                               | No |
| -h, --help                | Tool usage help information.                                                                  | No                                                                                                                                                                                            |

##### Advanced Function Parameters

| Parameter                             | Description                                                                                                                                                                                                                                                                                                                              | Required |
|---------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------| -------- |
| -db, --dym-batch                  | Dynamic batch parameter. Specifies the actual batch of the model input. <br>For example, during ATC model conversion, if --input_shape="data:-1,600,600,3;img_info:-1,3" --dynamic_batch_size="1,2,4,8" is set, the dym-batch parameter can be set to: --dym-batch 2.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | No       |
| -dhw, --dym-hw                    | Dynamic resolution parameter. Specifies the actual H and W of the model input. <br>For example, during ATC model conversion, if --input_shape="data:8,3,-1,-1;img_info:8,4,-1,-1" --dynamic_image_size="300,500;600,800" is set, the dym-hw parameter can be set to: --dym-hw 300,500.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | No       |
| -dd, --dym-dims                    | Dynamic dimension parameter. Specifies the actual Shape of the model input. <br>For example, during ATC model conversion, if --input_shape="data:1,-1;img_info:1,-1" --dynamic_dims="224,224;600,600" is set, the dym-dims parameter can be set to: --dym-dims "data:1,600;img_info:1,600".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | No       |
| -ds, --dym-shape                   | Dynamic shape parameter. Specifies the actual Shape of the model input. <br>For example, during ATC model conversion, if --input_shape_range="input1:\[8\~20,3,5,-1\];input2:\[5,3\~9,10,-1\]" is set, the dym-shape parameter can be set to: --dym-shape "input1:8,3,5,10;input2:5,3,10,10".<br>In dynamic shape scenarios, the output size of the model is usually 0 (that is, the memory size occupied by the output data is unknown). It is recommended to set the --output-size parameter.<br/>For example: --dymShape "input1:8,3,5,10;input2:5,3,10,10" --output-size "10000,10000"                                                                                                                                                                                                                                                                                                                                                                         | No       |
| -dr, --dym-shape-range              | The threshold range of the dynamic shape. If this parameter is set, inference is performed sequentially according to all Shape lists in the parameter to obtain summary inference information.<br/>For single input, the configuration format is: name:1,3,200\~224,224-300 or "name:1,3,200\~224,224-300". For example: --dym-shape-range name:1,3,200\~224,224-300 or --dym-shape-range "name:1,3,200\~224,224-300".<br/>For multiple inputs, the configuration format is "name1:1,3,200\~224,224-300;name2:1\~4,3,224,224". For example: --dym-shape-range "name1:1,3,200\~224,224-300;name2:1\~4,3,224,224".<br/>Where name is the model input name, "\~" indicates a range, and "-" indicates a value for a specific dimension. When configuring the dynamic shape range through the command line, only one set of dynamic range is supported. If there are multiple model inputs, separate them with semicolons (;). To ensure correct parameter recognition, enclose the entire configuration string in double quotes.<br/>When using an info file for configuration, multiple sets of dynamic shape ranges can be configured. In the *.info file, each configuration set should be placed on a separate line without quotes. Note that unnecessary blank lines between configuration lines should be avoided to prevent configuration errors. The info file format is as follows:<br/>x1:1,3,32,32;x2:1\~4,3,32,32<br/>x1:1\~4,3,32,32;x2:1,3,32,32<br/>For example: --dym-shape-range*.info. | No       |
| -outsize, --output-size          | Specifies the memory size occupied by the model output data. For multiple outputs, a value must be set for each output, separated by commas.<br>In dynamic shape scenarios, the output size of the model is usually 0 (that is, the memory size occupied by the output data is unknown). You need to estimate an appropriate size based on the input Shape and configure the memory size occupied by the output data.<br>For example: --dym-shape "input1:8,3,5,10;input2:5,3,10,10" --output-size "10000,10000"                        | No       |
| -asddm, --auto-set-dymdims-mode  | Auto-set dynamic dims mode. 1 or true (enabled), 0 or false (disabled). Disabled by default.<br/>For dynamic dims models, automatically sets Shape parameters based on the information of the input file. Note that the input data can only be npy files, because bin files cannot read Shape information.<br/>Used together with the input parameter. Invalid when used alone.<br/>For example: --input 1.npy --auto-set-dymdims-mode 1                                              | No       |
| -asdsm, --auto-set-dymshape-mode  | Auto-set dynamic shape mode. Values: 1 or true (enabled), 0 or false (disabled). Disabled by default.<br>For dynamic shape models, automatically sets Shape parameters based on the information of the input file. Note that the input data can only be npy files, because bin files cannot read Shape information.<br>Used together with the input parameter. Invalid when used alone.<br>For example: --input 1.npy --auto-set-dymshape-mode 1                                           | No       |
| -pf, --profiler                    | Profiler switch. 1 or true (enabled), 0 or false (disabled). Disabled by default.<br>Profiler data is in the profiler folder under the directory specified by the --output parameter. Used together with the --output parameter. Invalid when used alone. Cannot be enabled at the same time as --dump.<br/>If the environment has MSIT_NO_MSPROF_MODE=1 configured, the acl.json file is called when collecting performance data using the --profiler parameter.                                           | No       |
| --profiler-rename                       | Switch for modifying the file name of the profiler output file. When enabled, the output file name contains the model name information. 1 or true (enabled), 0 or false (disabled). Enabled by default. Used together with the --profiler parameter. Invalid when used alone.                                                                                                                                             |No|
| --dump                                  | Dump switch. 1 or true (enabled), 0 or false (disabled). Disabled by default.<br>Dump data is in the dump folder under the directory specified by the --output parameter. Used together with the --output parameter. Invalid when used alone. Cannot be enabled at the same time as --profiler.                                                                                                                        | No       |
| -acl, --acl-json-path               | acl.json file path. A valid json file must be specified. This file can configure profiler or dump. When this parameter is configured, the --dump and --profiler parameters are invalid. If profiler is configured in the json file, it is parsed into msprof command for profiling by default. If the environment has MSIT_NO_MSPROF_MODE=1 configured, performance data is collected using the acl.json configuration file method.                                                      | No       |
| --batch-size                            | Model batchsize. If this value is not input, it is automatically derived. The current inference module automatically groups batches based on model input and file output. The passed batchsize is only used for throughput calculation. The automatic derivation logic attempts to obtain the batchsize of the model by first obtaining the highest dimension of the first parameter as the batchsize. If it is dynamic batch, it is updated to the dynamic batch value. If it is dynamic dims and dynamic shape, it is updated to the highest dimension of the first parameter set. If the automatic derivation logic does not meet the requirements, be sure to pass in the accurate batchsize value to calculate the correct throughput. | No       |
| -oba, --output-batchsize-axis        | The batchsize axis of the output tensor. The default value is 0. When saving output result files, which axis is used to split the inference results. For example, if the batchsize is 2, it means 2 input files are grouped into a batch for inference. The batch dimension of the output result is on which axis. The default is axis 0, and it is split into 2 parts along axis 0. However, the output batch of some models is on axis 1, so this value needs to be set to 1. | No       |
| -aipp, --aipp-config               | The specific AIPP parameters that need to be configured before inference for an om model with dynamic AIPP configuration. Passed in as a .config file path. When the om model has dynamic AIPP configuration, this parameter is required. When the om model does not have dynamic AIPP configuration, configuring this parameter does not affect normal inference. |No|
| --backend                               | Specifies the trtexec switch. Needs to be specified as trtexec. Used together with the --perf parameter. Invalid when used alone.                                                           |No|
| --perf                                  | Switch for calling trtexec. 1 or true (enabled), 0 or false (disabled). Disabled by default. Used together with the --backend parameter. Invalid when used alone.                                         |No|
| -ec, --energy-consumption             | Energy consumption collection switch. 1 or true (enabled), 0 or false (disabled). Disabled by default. Needs to be used together with the --npu-id parameter. The default npu id is 0.                                         |No|
| --npu-id                                | Specifies the npu id. The default value is 0. The npu id corresponding to the specified device needs to be obtained through the npu-smi info command. Used together with the --energy-consumption parameter. Invalid when used alone.                |No|
| --pipeline                              | Specifies the pipeline switch, used to enable the multi-thread inference function. 1 or true (enabled), 0 or false (disabled). Disabled by default.                                                   |No|
| --dump-npy                              | Specifies the dump-npy switch, used to enable the automatic conversion of dump results. 1 or true (enabled), 0 or false (disabled). Disabled by default. Needs to be used together with the --output and --dump/--acl-json-path parameters. Invalid when used alone. |No|
| --threads                               | Specifies the threads switch, used to set the number of compute threads for multi-compute thread inference. The default value is 1. The value range is positive integers greater than 0. Needs to be used together with the --pipeline 1 parameter. Invalid when used alone. |No|
